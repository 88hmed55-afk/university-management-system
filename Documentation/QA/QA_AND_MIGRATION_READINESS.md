## 1. النطاق

يوثّق هذا الملف ما تم التحقق منه فعلياً في المستودع، وما يزال بوابة مفتوحة. لا يُفترض أي سياسة جامعية أو هدف أداء أو جدول نسخ احتياطي من عند المطور.

## 2. مصفوفة مستويات الاختبار

| المستوى | الحالة | الدليل |
|---|---|---|
| Unit لقواعد الحالات والحساب | جزئي | المنطق يُختبر عبر إجراءات Feature في جميع الوحدات؛ لا توجد مجموعة Unit منفصلة تتجاوز هيكل Laravel الابتدائي. |
| Feature/Integration | مغطّى | `php artisan test --compact` — 195 اختباراً بعد إضافة `QaAndMigrationReadinessTest`، تشمل المعاملات والصلاحيات والتدقيق وidempotency. |
| Browser/E2E | **متبقٍ** | بوابة الإطلاق في `docs/11` تتطلب مسارات مستخدم كاملة؛ لم تُنفَّذ آلياً بعد. |
| Security | مغطّى جزئياً | اختبارات IDOR ونطاق الحرم وانتهاء التفويض في `IdentityRbacFoundationTest` و`QaAndMigrationReadinessTest`؛ اختبار الجلسات والملفات ما زال يدوياً. |
| Data integrity | مغطّى | `DataIntegrityAudit` يفحص orphan rows والتكرارات، ويُختبر منع الحذف عبر قيد FK، وثبات سجلات التدقيق. |
| Performance | **متبقٍ** | يعتمد على سيناريو حمل تعتمده الجامعة (P-019). الأرقام الواردة في `docs/11` هدف مراجعة أولي وليس التزاماً. |
| UAT | **متبقٍ** | قوائم حسب الدور في TASK-025. |
| Disaster recovery | **متبقٍ** | مطلوب قرار RPO/RTO (P-020) واختبار استعادة فعلي؛ انظر `RPO_RTO_DECISION_REQUEST.md`. |

## 3. فحوص جاهزية الترحيل

- ✅ جميع الجداول التي تُنشئها ملفات `database/migrations` موجودة بعد `php artisan migrate --force` على SQLite محلياً.
- ✅ قيود المفاتيح الأجنبية تمنع الحذف الصامت للسجلات المرجعية؛ يُختبر ذلك على مستوى قاعدة البيانات لا في الواجهة فقط.
- ✅ الفهارس الفريدة للحقول الجوهرية موجودة، وفحص التكرارات يعيد صفراً.
- ✅ سجلات التدقيق والتشغيلات والتصدير غير قابلة للتعديل أو الحذف.
- ✅ بوابة CI على `push` و`pull_request` تشغّل migrations واختبارات وفحص التنسيق (`.github/workflows/tests.yml`).
- ⚠️ لم يُجرَ اختبار collation على MySQL (R-006)؛ البيئة المحلية المعتمدة SQLite مع MySQL كبديل موثّق.
- ⚠️ أي ترحيل إنتاجي يجب أن يسبقه نسخ احتياطي متسق ومراجعة أثر؛ جدول الاحتفاظ والنسخ سياسة جامعية معلّقة (P-018/P-020).
- ⚠️ دوال `down()` في الملفات الحالية تحذف الجداول؛ لا تُستخدم كخطة رجوع إنتاجية. الرجوع المعتمد هو استعادة نسخة مختبرة في بيئة معزولة.

## 4. الاستيراد التجريبي للبيانات المرجعية

### 4.1 القائمة المغلقة

`ReferenceDataCatalog` يعرّف مجموعتين فقط، ومصدرهما `docs/05_roles_permissions.md`:

| الرمز | المحتوى | المصدر |
|---|---|---|
| `data_scopes` | نطاقات البيانات المعتمدة | `docs/05_roles_permissions.md` |
| `roles` | الأدوار المعتمدة وربطها بالنطاق | `docs/05_roles_permissions.md` |

لا تُقبل أي مجموعة أخرى (مثل درجات أو عملات أو سياسات) لأنها سياسات جامعية معلّقة.

### 4.2 طريقة الاستخدام

```bash
php artisan qa:validate-reference-import path/to/roles.json --set=roles
php artisan qa:validate-reference-import path/to/data_scopes.json --set=data_scopes
```

صيغة الصفوف:

```json
[
  { "code": "report_reader", "data_scope": null, "is_system": true },
  { "code": "campus_manager", "data_scope": "campus", "is_system": true }
]
```

### 4.3 ما يفعله الفحص

- يتحقق من دور الفاعل (`system_admin` أو `identity_admin`).
- يرفض الحقول غير المعتمدة، والرموز غير المعتمدة، والتكرار داخل الملف، ونطاقاً غير موجود قبل استيراد النطاقات.
- يميّز بين صف يُدرج وصف يُخطى لتطابقه مع بيانات موجودة.
- **لا يكتب أي شيء في الجداول المستهدفة**؛ القيمة `writes_performed` دائماً `0`.
- يعيد رمز خروج صفري عند خلو الملف من الأخطاء، ورمز فشل عند وجود أخطاء.

لا توجد حالياً عملية استيراد نهائي مُفعّلة؛ تفعيلها يتطلب ملفاً معتمداً ومرجع قرار، حتى لا يُنشأ سجل سياسة من اجتهاد المطور.

## 6. الخلاصة

الترحيل جاهز من ناحية سلامة المخطط والاختبارات الآلية والفحص الجاف للبيانات المرجعية، لكن **بوابة الإطلاق ليست مكتملة**: سيناريو الأداء، واختبار الاستعادة، وقوائم UAT، وقرارات السياسات المعلّقة يجب أن تُغلق أولاً.
