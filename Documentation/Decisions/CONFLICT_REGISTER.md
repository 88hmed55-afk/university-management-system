## C-001 — تعارض سلسلة الأدوات (PHP / Composer) — **حاجز**

| الحقل | التفصيل |
|---|---|
| **الوصف** | المخطط يستهدف Laravel 13 الذي يشترط PHP ≥ 8.3 (تحقّق من الوثائق الرسمية بتاريخ 17 نوفمبر 2026). الواقع المحلي: `C:\xampp\php\php.exe` = **PHP 8.2.12** (ZTS). كما أن **Composer غير مثبّت** ولا يوجد على PATH ولا كحزمة عامة. |
| **الدليل** | `php -v` (عبر المسار المباشر)، `composer --version` = CommandNotFound، فحص `%APPDATA%\Composer` و`C:\xampp` = لا Composer. |
| **الأثر الهندسي** | لم يكن ممكناً إنشاء مشروع Laravel 13؛ ولا تثبيت الحزم؛ Gate 0 كان مستحيلاً. أي محاولة كانت ستؤدي إلى فشل `composer create-project` أو أخطاء توافق إصدارات. |
| **الحل المقترح (الأفضل)** | تثبيت PHP 8.3+ (أو XAMPP أحدث) + Composer، والإبقاء على Laravel 13 كما وثّق المخطط. يحافظ على خط الأساس المعتمد ويجنّب تعديل الوثائق. |
| **البديل الموثّق** | اعتماد **Laravel 12** (يدعم PHP 8.2 حسب الوثائق الرسمية) عبر ADR جديد، مع تثبيت Composer. يوفّر وقت الترقية لكنه يغيّر خط الأساس ويحتاج تحديث `TECHNICAL_REFERENCES.md` و`docs/07`. |
| **القرار المطلوب** | سؤال واحد من صاحب المشروع (E-001). لا أختار عن الجامعة في تغيير التقنية دون مبرر موثق. |
| **القرار الفعلي** | المالك اعتمد ترقية PHP إلى 8.3+ وتثبيت Composer والإبقاء على Laravel 13 (17 نوفمبر 2026). نُفّذ بـ PHP 8.3.36 + Composer 2.11.2. |
| **الحالة** | `RESOLVED` — لم يعد حاجزاً؛ التفاصيل في `LOCAL_SETUP.md` |

## C-002 — تعارض محرك قاعدة البيانات المحلية — **حاجز جزئي**

| الحقل | التفصيل |
|---|---|
| **الوصف** | المستهدف: MySQL 8.4 LTS. المتاح فعلياً: MariaDB **10.4.32** داخل XAMPP، وMySQL **8.0.38** في `C:\Program Files\MySQL\MySQL Server 8.0\bin`. |
| **الدليل** | `mysql --version` لكلا المسارين. |
| **الأثر الهندسي** | فروق في أنواع الأعمدة/الفهارس/دلالات Collation والـ CHECK constraints قد تظهر في migrations؛ Collation العربي يجب اختباره فعلياً قبل الاعتماد (الوثيقة 6 تشترط ذلك). |
| **الحل المقترح** | استخدام MySQL 8.4 LTS محلياً إن أمكن؛ وإلا MySQL 8.0.38 (أقرب خط إصدار) مع توثيق الفروق وتجنّب ميزات 8.4-specific في migrations، واختبار collation عربي فعلي. |
| **القرار المطلوب** | ضمن نفس السؤال الحاجز (E-002). |
| **القرار الفعلي** | اختير MySQL 8.0.38 كبديل موثّق لأن 8.4 LTS غير مثبّت محلياً. الفروق موثّقة في `LOCAL_SETUP.md`. |
| **الحالة** | `RESOLVED`؛ مخاطرة تشغيلية `R-006`: خدمة `MYSQL80` متوقفة وتحتاج صلاحية إدارة |

## C-003 — تعارض توجيهي في التصميم — **حُلّ هندسياً**

| الحقل | التفصيل |
|---|---|
| **الوصف** | أمر المشروع يطلب «هوية تقنية استثنائية / Premium Institutional Technology / Advanced Data Visualization» بأعلى أولوية، بينما الوثيقة 8 تطلب «واجهة مؤسسية هادئة وعملية، لا تفرط في البطاقات والتدرجات والظلال»، والأمر يمنع القوالب الجاهزة والـ Glassmorphism. |
| **الأثر الهندسي** | خطر الإفراط في الزخرفة على حساب الوضوح، أو العكس: مظهر باهت لا يرقى لمستوى المنتج المؤسسي. |
| **الحل المعتمد** | اعتبار «التميّز» ناتجاً عن: طباعة عربية متقنة، شبكة دقيقة، تدرّج هرمي واضح، مساحات بيضاء مدروسة، تصور بيانات غني (SVG خطي/شريطي/مؤشرات)، وخطوط رقيقة متسقة. **لا** تدرجات لونية كثيرة، **لا** glassmorphism، **لا** ظلال ثقيلة، **لا** بطاقات متطابقة. طُبّق في `DESIGN_SYSTEM.md` و`design-approval-mockups.html`. |
| **الحالة** | `RESOLVED` — يُعاد النظر فقط إذا اعترض صاحب المشروع أثناء Design Approval. |

## C-004 — فجوة تتبع بين أمر المشروع وكتالوج الشاشات — **مقترح حل**

| الحقل | التفصيل |
|---|---|
| **الوصف** | الأمر يطلب صراحةً 8 تجارب دورية مستقلة (رئيس الجامعة، مدير الحرم، عميد الكلية، رئيس القسم، القبول والتسجيل، عضو هيئة التدريس، الطالب، المتقدم). الكتالوج يوفّر `SCR-001` (لوحة الجامعة) و`SCR-093…099` (Portals)، لكنه لا يسمّي لوحات مستقلة لمدير الحرم والعميد ورئيس القسم ولا «مساحة عمل القبول التشغيلية» كشاشة منفصلة. |
| **الأثر الهندسي** | غياب معرّفات في مصفوفة تتبع المتطلبات (RTM) → خطر بناء واجهة بلا متطلب موثق، أو نسيان لوحة عند توزيع الصلاحيات. |
| **الحل المقترح** | (أ) لوحة رئيس الجامعة = `SCR-001` موسّعة. (ب) لوحة مدير الحرم = مركّبة من `SCR-014` + `SCR-020` + `SCR-055` + تقارير `RPT`. (ج) لوحة العميد = `SCR-017` + `SCR-041` + `SCR-086`. (د) لوحة رئيس القسم = `SCR-018` + `SCR-050` + `SCR-061`. (هـ) مساحة القبول = `SCR-028…033` كواجهة تشغيلية خطواتية. تُضاف معرّفات مرجعية `SCR-100…SCR-103` في RTM دون حذف وظيفة. |
| **الحالة** | `RESOLVED` — اعتمد المالك التصميم كاملاً في 17 نوفمبر 2026 (E-004)؛ تُسجَّل المعرّفات المرجعية SCR-100… في RTM عند إنشاء مصفوفة التتبع. |

## C-005 — غياب تأكيد تطابق PHP CLI مع PHP الخاص بخادم التطوير — **مفتوح**

| الحقل | التفصيل |
|---|---|
| **الوصف** | الوثيقة 7 تشترط أن يكون PHP CLI هو نفسه إصدار PHP لتشغيل التطبيق. فُحص CLI فقط عبر `C:\xampp\php\php.exe`؛ لم يُفحص بعد إصدار وحدة Apache في XAMPP (`phpinfo()` عبر الويب). |
| **الأثر الهندسي** | اختلاف الإصدار يسبب أخطاء يصعب تتبعها بين Composer و`php artisan serve`. |
| **الحل المنفَّذ** | وحدة Apache في XAMPP ما زالت PHP 8.2.12. لتفادي عدم التطابق، سيُشغَّل التطبيق عبر `php artisan serve` باستخدام PHP المحمول 8.3.36 نفسه المستخدَم في CLI. لا يُستخدم Apache/XAMPP لتشغيل هذا المشروع. |
| **الحالة** | `RESOLVED` لمسار التطوير المعتمد؛ XAMPP Apache مستبعد |
