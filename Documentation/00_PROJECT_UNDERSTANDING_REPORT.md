## 2. هويّة المشروع ونطاقه (حقائق معتمدة)

- **الاسم:** University Management System (UMS).
- **النوع:** جامعة أهلية خاصة واحدة في صنعاء – اليمن، متعددة الأحرم. **ليست** منصة متعددة الجامعات.
- **الحجم المستهدف:** 1,000–5,000 طالب تقريباً.
- **المسارات:** بكالوريوس وماجستير ودكتوراه (التفاصيل التنفيذية للدراسات العليا معلقة على لوائحها).
- **الإدارة:** مركزية موحدة للسياسات والاعتمادات؛ تفويض تشغيلي محلي لمديري الأحرم.
- **الفصل المؤسسي (مبدأ جوهري):**
  - المسار الأكاديمي: إدارة أكاديمية مركزية ← عميد الكلية ← رئيس القسم ← عضو هيئة التدريس.
  - المسار التشغيلي المكاني: إدارة مركزية ← مدير الحرم ← موظفو التشغيل والمرافق.
  - مدير الحرم **ليس** رئيساً أكاديمياً للعمداء؛ والعميد **لا** يدير المرافق تلقائياً. يتعاون المساران ولا يندمجان.
  - الكلية قد تعمل في أكثر من حرم، والحرم يستضيف أكثر من كلية (علاقة مؤرخة متعدد إلى متعدد).
- **البرامج:** لكل برنامج كلية رئيسية واحدة + كليات مشاركة بعلاقة مؤرخة. السجل الأكاديمي والقبول والتخرج يظلان تحت برنامج واحد.
- **المقررات:** كتالوج مركزي؛ المقرر الواحد يُستخدم في عدة خطط دون نسخ.
- **التوسع:** إضافة حرم/كلية/قسم/برنامج من الواجهة دون تعديل كود (ضمن السياسات المعتمدة).
- **قاعدة البيانات:** مركزية واحدة قابلة للكتابة؛ لا قواعد كتابة مستقلة لكل حرم.

## 4. التحليل المؤسسي المستخرج (جاهز للـ SRS)

### 4.1 أصحاب المصلحة وملكية القرار
رئاسة/مجلس الجامعة (اعتماد الهيكل والسياسات)، الشؤون الأكاديمية، القبول والتسجيل، المالية، الموارد البشرية، مديرو الأحرم، العمداء ورؤساء الأقسام، تقنية المعلومات، فريق التطوير.

### 4.2 الوحدات والأولويات (19 وحدة)
`CORE` `IAM` `ORG` `HR` `ADM` `STD` `ACA` `REG` `TMT` `ATT` `EXM` `FIN` `DOC` `MSG` `PG` `LIB` `RPT` `AUD` `INT`.  
P0: CORE, IAM, ORG, ADM, STD, ACA, REG, FIN, AUD. P1: HR, TMT, ATT, EXM, DOC, MSG, RPT. P2: PG, LIB, INT (PG حسب جاهزية الجامعة).

### 4.3 سير العمل الرئيسية المستخرجة
1. **القبول:** دورة ← طلب متقدم ← مستندات ← مراجعة/اختبار عند السياسة ← توصية/قرار ← إشعار ← تحقق من التكرار ← تحويل idempotent إلى سجل طالب ← استحقاق مالي. استثناءات: ناقص، مكرر، تغيير رغبة، رفض العرض، تأجيل، مستند مشكوك، انقطاع شبكة.
2. **التسجيل:** فتح نافذة ← أهلية وخطة ← شعب مسموحة (متطلبات/سعة/تعارض) ← إضافة/حذف/انسحاب ← إقفال وقوائم نهائية ← حفظ لقطة ما انطبق من خطة/مقرر/شعبة/رسوم/سياسة. **المالية لا تمنع التسجيل تلقائياً إلا بقاعدة معتمدة ومع سبب ومسار مراجعة.**
3. **الجدولة:** فترات ← طرح ← شعب ← إسناد مدرسين ← قاعات ← اجتماعات ← كشف تعارضات ← نشر وإشعار ← حفظ تاريخ التغيير.
4. **الحضور/النتائج:** جلسات ← حالات ← قفل إدخال ← عناصر تقييم معتمدة ← درجات مسودة ← مراجعة واعتماد ← نشر ← اعتراض موثق. **لا تعديل صامت لمنشور.**
5. **المالية:** سياسات مؤرخة ← استحقاقات/فواتير ← دفعات وإيصالات ← تخصيص ← كشف حساب ← رد/عكس/تسوية ← إقفال صندوق ومطابقة. الأموال `DECIMAL` + رمز عملة.
6. **الوثائق/الطلبات/الإشعارات:** لكل طلب نوع/مقدم/حالة/مرفقات/مسؤول/مسار/قرار؛ لكل وثيقة رقم/نوع/مالك/تاريخ/سرية/إصدارات؛ الإشعارات داخلية أولاً.

### 4.4 الأدوار ونطاقاتها (24 دوراً)
من «مدير النظام التقني» (بلا سلطة مالية/أكاديمية تلقائية) إلى «متقدم» (طلبه فقط). النموذج **RBAC + نطاق بيانات + سياق عملية**. الدور وحده لا يفتح السجلات. فصل المهام إلزامي: منشئ الرسوم ≠ معتمدها، أمين الصندوق لا يمحو إيصالاً، المدرس يدخل والمعتمد ينشر، تقنية المعلومات لا تعتمد أكاديمياً/مالياً بصفته التقنية.

### 4.5 الكيانات والمبادئ الحاكمة للبيانات
- فصل: `people` عن `users` عن `employees/students`؛ والدور عن نطاق البيانات؛ والموقع الجغرافي عن الكلية/القسم/البرنامج.
- إصدارات وتأريخ: `course_versions`, `study_plan_versions`, `program_versions`, `fee_policies`، وعلاقات `effective_from/effective_to/مرجع قرار`.
- الطالب مرتبط بإصدار خطة محدد؛ إصدار جديد **لا ينقل** الطلاب تلقائياً.
- تحويل متقدم→طالب **idempotent**؛ لا ازدواج شخص/طالب.
- قيود: لا تسجيلين نشطين في الشعبة نفسها؛ لا حجز متعارض لقاعة/مدرس زمنياً؛ لا نشر درجات غير معتمدة؛ أرقام الفواتير/الإيصالات فريدة ولا يُعاد استخدام الملغى؛ كل رد/عكس مرتبط بالأصل؛ كل ملف له checksum ومetadata.
- الأموال `DECIMAL` لا FLOAT؛ لا ملفات طلاب داخل MySQL؛ لا JSON بديلاً عن علاقة قابلة للبحث؛ لا soft-delete تلقائي للعمليات الأكاديمية/المالية.

### 4.6 جرد الشاشات (99)
SCR-001…SCR-006 (CORE)، SCR-007…012 (IAM)، SCR-013…020 (ORG)، SCR-021 (PEOPLE)، SCR-022…025 (HR)، SCR-026…033 (ADM)، SCR-034…039 وSCR-064…065 (STD)، SCR-040…047 (ACA)، SCR-048…053 (REG)، SCR-054…056 (TMT)، SCR-057…058 (ATT)، SCR-059…063 (EXM)، SCR-066…070 (PG)، SCR-071…076 (FIN)، SCR-077…079 (DOC)، SCR-080…081 (MSG)، SCR-082…083 (LIB)، SCR-084…088 (RPT)، SCR-089…092 (AUD)، SCR-093…099 (PORTAL).  
كل شاشة موصوفة بـ: الهدف، المعلومات، الإجراءات، المستخدمون، قواعد العمل، والسلوك القياسي (تحقق/صلاحية/تدقيق/منع نقر مكرر).

### 4.7 ما أضافه أمر المشروع على المخطط (التزامات جديدة)
- **تجارب دورية مستقلة صراحةً:** لوحة رئيس الجامعة، لوحة مدير الحرم، لوحة عميد الكلية، لوحة رئيس القسم، مساحة عمل القبول والتسجيل (تشغيلية لا لوحة معلومات)، مساحة عضو هيئة التدريس، بوابة الطالب، بوابة المتقدم. (المخطط يذكر SCR-001 و SCR-093…099 لكنه لا يسمّي أربع لوحات دورية بشكل مستقل — انظر C-004).
- **أنواع واجهات متمايزة إلزامياً:** Dashboard / Data Management / Detail / Form / Approval / Schedule / Academic / Financial / Reporting — شخصية مختلفة لكل نوع وهوية بصرية واحدة.
- **واجهات متخصصة:** إدارة القبول خطواتية، جدول أكاديمي أسبوعي/يومي مع تعارضات، ملف أكاديمي بـ Timeline، مسار بحث علمي للدراسات العليا لا يطابق البكالوريوس، حركات مالية دقيقة لا تعتمد اللون وحده للحالة.
- **Design Approval إلزامي قبل التعميم** بـ15 بنداً محدداً.
- **أولوية قصوى للتصميم** مع منع القوالب الجاهزة والتدرجات المفرطة والـ Glassmorphism والظلال الثقيلة وبطاقات متشابهة.

## 5. القرارات المعتمدة مقابل السياسات المعلقة

### 5.1 معتمد/موصى به هندسياً (D-001…D-012)
جامعة واحدة متعددة الأحرم؛ مركزية السياسات مع تفويض تشغيلي؛ مدير حرم يتبع الإدارة إدارياً؛ عميد مستقل يتبع المسار المركزي؛ رئيس قسم يتبع العميد (D-005 نموذج عمل معتمد مبدئياً ويُطابق الهيكل الرسمي لاحقاً)؛ برنامج بكلية رئيسية ومشاركات؛ كتالوج مقرر مركزي؛ Modular Monolith؛ Laravel + MySQL + XAMPP؛ عربي RTL + إنجليزية؛ كلية في أكثر من حرم؛ هوية شخص واحدة بملفات أدوار منفصلة.

### 5.2 سياسات تنتظر الجامعة (P-001…P-024)
أسماء الأحرم، الهيكل الرسمي، نظام الساعات، التقويم، شروط القبول، أنماط الأرقام، التقديرات والمعدل، الحضور والحرمان، حدود التسجيل، التحويل والمعادلة، التخرج، الرسوم والعملات، التقسيط والمنح، صلاحيات الصندوق، لوائح HR، لوائح الدراسات العليا، قواعد المكتبة، الاحتفاظ والخصوصية، التزامن والأداء، RPO/RTO، مزودو التكامل، النماذج والأختام، انقطاع الشبكة، الحاجة لمحاسبة عامة كاملة.

**قاعدة حاكمة:** يجوز بناء الآليات والهياكل القابلة للإصدار (حقل `policy_version`، حالة مسودة، منع النشر غير المعتمد)؛ **لا يجوز** اختراع قيمة سياسة (نسبة، عملة، حد، درجة، يوم دوام) أو اعتبارها حقيقة تشغيلية.

## 7. الافتراضات التي لا تتحول إلى حقائق
- الأعداد والأسماء النهائية للأحرم والكليات والأقسام والبرامج غير معروفة.
- لا رسوم ولا شروط قبول ولا تقويم نهائي معتمد.
- لا نظام ساعات/وحدات قبل اعتماد الشؤون الأكاديمية.
- لا يُستنتج عدد المستخدمين المتزامنين من عدد الطلاب.
- الماجستير والدكتوراه ضمن الرؤية لكن تفاصيلهما تنتظر اللوائح.
- دعم البرامج المشتركة في التصميم ≠ قرار بإطلاق برنامج مشترك الآن.
