# 4. جرد صفحات النظام — وصف تفصيلي لكل شاشة

هذه قائمة التصميم الوظيفي للواجهات. قبل التنفيذ قد تدمج صفحات أو تفصلها بناءً على اختبار تجربة المستخدم، لكن لا تحذف وظيفة أو قاعدة عمل دون تحديث سجل المتطلبات. كل صفحة تتبع قالباً موحداً: هدف، معلومات، إجراءات، صلاحيات، تحقق، حالات واجهة، وتدقيق.

## القواعد المشتركة
- كل قائمة بها بحث وفلاتر وفرز وترقيم صفحات وحالة فارغة ورسالة خطأ واضحة.
- كل نموذج يظهر الإلزامية، الوصف، حدود المدخلات، رسائل التحقق، ويحافظ على القيم عند الفشل.
- الإجراء الحساس يعرض أثره ومرجعه قبل التنفيذ؛ لا حذف صامت للسجلات التاريخية.
- صلاحيات الخادم هي المرجع؛ إخفاء الزر وحده ليس حماية.
- كل تنزيل/تصدير يخضع لنطاق الصلاحية نفسه المطبق على الصفحة.
- اتجاه RTL أصلي؛ الأكواد والأرقام والبريد تعزل كـ LTR عند الحاجة.
- كل شاشة تعالج التحميل والفراغ وعدم وجود نتائج وفشل الشبكة وعدم الصلاحية وانتهاء الجلسة.

**المعلومات والحقول:** الفترة، المقرر، الشعبة، المدرس، القاعة، الدرجة المنشورة  
**الإجراءات:** عرض، تنزيل، طباعة، إشعار  
**المستخدمون:** الطالب  
**قواعد العمل والتحقق:** لا مسودات أو نتائج غير معتمدة  
**السلوك القياسي:** حفظ وإظهار نتيجة واضحة؛ منع النقر المكرر في العمليات المالية/الأكاديمية؛ تسجيل الفعل والفاعل والوقت والسبب عند حساسية العملية؛ تنفيذ التحقق والصلاحية في الخادم.
