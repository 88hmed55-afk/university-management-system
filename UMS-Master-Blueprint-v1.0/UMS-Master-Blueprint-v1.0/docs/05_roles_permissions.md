# 5. الأدوار والصلاحيات ونطاق الوصول

## النموذج
يعتمد RBAC (دور + أذونات) مع نطاق بيانات وسياق العملية. النطاقات الممكنة: المؤسسة، الحرم، الكلية، القسم، البرنامج، الشعبة/المقرر، والذات (الطالب أو المستخدم نفسه). وقد تستخدم شروط إضافية مثل أن التسجيل مفتوح، أو المعاملة في حالة قابلة للاعتماد، أو التفويض ساري المفعول. الدور وحده لا يفتح جميع السجلات.

المصفوفة مبدئية ولا تصبح قائمة صلاحيات نهائية إلا بعد اعتماد الجامعة. لا تمنح صلاحية حساسة بناءً على المسمى وحده.

## فصل المهام (SoD)
- منشئ سياسة الرسوم لا يعتمدها وحده إذا تتطلب الرقابة فصل مهام.
- أمين الصندوق لا يمحو إيصالاً؛ الرد/العكس يحتاج مراجعة واعتماداً.
- المدرس يدخل الدرجة؛ المعتمد يراجع وينشر وفق اللائحة.
- مدير النظام التقني لا يمنح نفسه اعتماداً مالياً أو أكاديمياً.
- مدخل قرار القبول لا يعتمد وحده إذا نصت اللائحة على لجنة.

## التنفيذ الأمني
- التحقق عبر Middleware + Policies/Gates + نطاقات الاستعلام.
- لا تجلب سجلات خارج النطاق ثم تخفيها في الواجهة.
- اختبار IDOR بتغيير معرف السجل في URL/API.
- السجلات الجماعية والتصدير والطباعة تخضع لنفس النطاق.
- التفويض له بداية ونهاية وسبب ومعتمد، ولا يسمح بالتفويض الذاتي أو توسيع صلاحية محظورة.
- انتهاء تكليف الموظف يعيد تقييم/ينهي الأدوار المرتبطة بالتكليف.
- مراجعة دورية للصلاحيات وإقرار من مالك الوحدة.
